# エラー画面

作成日時: 2026年8月27日 10:16
タグ: Phase1

# 機能概要

存在しないページ・権限のないページ・システム障害時にユーザーへ状況と復帰導線を示す画面。

表示トリガは「新クラ：error / validation / filter まとめ」スプレッドシートの error シート（確定）に従い、ビジュアル・文言は Figma「エラー画面」ページに準拠する。

# 機能要件

## 404（NotFound）

- トリガ: 存在しない URL へのアクセス、および初期表示の API 404 応答（細かいエラーハンドリングはこの画面で吸収）
- 表示: ログイン済みレイアウト内（サイドバー・ヘッダーあり）。イラスト + 「404 Page Not Found」+「アクセスしようとしたページは見つかりませんでした。」+「トップページ」ボタン
- 未ログイン時: 不明 URL は一律 /login へリダイレクト（既存の認証ガードどおり。非ログイン状態で 404 画面を見せる場面は生じない）

## 403（Forbidden）

- トリガ: 初期表示の API 403 応答（submit 時の 403 はモーダル「認証エラーが発生しました」— error シートどおり別扱い）
- 表示: ログイン済みレイアウト内。イラスト + 「403 Forbidden」+「閲覧権限がありません」+「ページの閲覧には権限が必要です。管理者へ権限の付与を依頼してください。」+「トップページ」ボタン

## 500（Internal Server Error）

- トリガ: S3 障害・タイムアウト等でアプリを配信できないとき CloudFront が静的 500.html を返す（error シートどおり）。初期表示の API 5xx も本画面へ遷移する
- 表示: サイドバー・ヘッダー無しのスタンドアロン。イラスト + 「500 Internal Server Error」+「アクセスしようとしたページは表示できませんでした。」+「トップページ」ボタン + コピーライトフッター
- ランタイムエラーは何もしない（error シートどおり。現行実装はフレームワーク既定のエラー表示のため、「何もしない」の意味 = 現状のままで良いかも確認したい）
- 初期表示時のネットワークエラー（API 応答なし）の扱いは error シートに定義がなく空白。500 画面と同扱いで良いか確認したい

# 共通

- 「トップページ」ボタンは / へ遷移（ログイン状態・権限に応じた既存の振り分けに従う）
